# 前端交付范围

本次按方案 A 整理当前线上页面的前端资源。目标是形成可阅读、可安装、可构建的前端源码仓库，不迁移服务端实现，也不改造材料页的 Gradio 业务流程。

## 各目录交付内容

| 目录 | 包含内容 | 运行边界 |
| --- | --- | --- |
| `apps/portal` | 平台首页、模型对话、科学数据中心、智能体入口及医学知识问答的 React/TypeScript/CSS、静态图片、依赖和构建配置 | 可独立开发与构建；模型回答、服务状态、医学问题推荐及资料引用需要现有 API |
| `apps/robot` | 机械臂页面、主题菜单、语音和手势交互 UI、手动控制 UI、前端类型和接口调用、依赖和构建配置 | 可独立开发与构建；会话、遥测、视频、语音识别及设备操作需要现有服务 |
| `materials-ui` | 安全提取的 banner/head HTML 片段、页面 CSS、浏览器主题脚本 | 外观资源快照，不是可独立运行的材料工作台 |
| `shared` | 线上公共 banner CSS、主题脚本和 Logo | 供前端引用、对照和后续维护；并非所有页面都已改为直接导入此目录 |
| `scripts` | 本地依赖安装、前端构建、静态预览、源码上传范围检查 | 开发工具，不包含线上服务启动或部署配置 |

科学数据中心保留前端展示用的数据条目及公开链接，不打包链接指向的数据集文件。问答历史和机械臂会话以应用现有浏览器存储逻辑运行，不附带线上用户数据。

## 保留线上样式的方式

门户的公共静态资源位于 `apps/portal/public/`，机械臂的静态资源位于 `apps/robot/public/`。`shared/` 同时保留公共资源源码快照，便于识别共享的 banner、主题和 Logo。

机械臂当前使用 `apps/robot/src/AgentMasthead.css` 等应用内样式，本次继续保留其线上实现，不用公共文件强行覆盖。材料页 CSS 依赖 Gradio 所生成的元素结构和 ID；脱离对应结构后，不能仅靠这些样式还原完整页面。

## 未纳入内容

- 后端路由、业务回调、Python/Gradio 服务实现及服务端依赖。
- 模型权重、向量库、医学知识库原始资料和数据集正文。
- 数据库、用户上传文件、问答历史、设备运行数据和日志。
- API 密钥、访问令牌、SSH 凭据、真实环境变量文件和账号配置。
- 服务器地址清单、反向代理配置、服务管理配置、容器或线上启动脚本。
- 依赖安装目录、构建产物、缓存、备份和临时文件。

应用中的前端 API 调用和 TypeScript 数据结构属于前端对接代码，保留在仓库中；接口的服务端实现不随仓库上传。

## 材料筛选的明确限制

原材料页由 Gradio 生成，组件声明和业务事件绑定位于服务端代码中。方案 A 不上传这些代码，也不把它们转换成新的前端应用。因此，本仓库不包含材料页完整的组件树、文件上传处理、会话管理、推理、检索或流式回答逻辑。

`materials-ui` 中的 HTML 是片段，CSS 是原有结构的外观规则，主题脚本只负责浏览器侧外观切换。根目录 `build` 不会将它们生成为可独立使用的材料筛选页面。门户入口默认继续链接 `/agent/materials/`，该地址需由现有服务提供。

## 配置与构建边界

为便于脱离原访问地址开发，公开 API 根地址、开发代理目标以及门户中的机械臂和材料页入口可通过环境变量配置。默认使用同源相对路径。具体配置见 [接口对接说明](api-integration.md)。

两套 React 应用分别安装、校验和构建，根构建脚本将静态产物合并为一个 `dist/`。这只完成前端打包，不安装或启动后台服务，也不包含线上托管配置。

上传 GitHub `main` 仅保存此处列出的源码和文档，不代表网站已经发布。
